# Expanded rule coverage delivery plan

Baseline is merged main at `c123d48`. This plan covers both recommendation
lists. All rule names below describe proposed behavior until conformance
and end-to-end tests verify it.

## 1. Catalog and reporting

Keep the existing primary categories and stable rule IDs. Add qualified
`metadata.subcategory` labels and expose them in rule listing, explain,
and JSON reports. Add a subcategory selector that combines with the
existing aspect selector and works consistently for static and framework
findings. Preserve existing results for commands without a selector.
Add a reliability review grouping and verify that choosing it includes
timeouts, retries, backpressure, cancellation, and shutdown. Promote
reliability to a primary category only with compatible aspect filtering
and published report behavior. Tag existing rules in areas where the
baseline already has coverage so the grouping is usable immediately.
Correct the inventory entry for the existing shotgun-surgery and
divergent-change analyzers.

In the first implementation, `autoreview diff --static-only --subcategories reliability`
selects the `reliability.*` labels. Comma-separated selectors match any
listed label or group. When `--aspects` is also supplied, a finding must
match both filters.

Acceptance cases include one finding with multiple subcategories, a
rule without metadata, existing filtering by correctness and security,
and a candidate from each engine that participates in the grouping.

## 2. Recognized local APIs

Share JavaScript and TypeScript definitions through the family compiler
and exercise the TypeScript variants on TSX. Resolve imports or known
framework context before relying on a method name. Mark ambiguous findings
advisory. Each row specifies a failing example and a nearby passing one.

| Subcategory | First implementation and acceptance cases |
| --- | --- |
| `time.calendar-formatting` | Java and Kotlin DateTimeFormatter patterns mixing a week-based year with calendar month/day. Match `YYYY-MM-dd` and pass `uuuu-MM-dd`, ISO week-date patterns, and custom similarly named types. |
| `frontend.render-identity` | JSX keys generated by Math.random in render. Pass stable keys and random values assigned once outside render. |
| `testing.property-execution` | Discarded fast-check `check` result from a recognized import. Pass results whose failure is checked and `fc.assert` with appropriate awaiting. |
| `testing.assertions` | Jest synchronous `toThrow` on inline async callback. Pass synchronous throws, awaited rejection matchers, and unrelated matchers outside known Jest context. |
| `accessibility.keyboard` | Clickable intrinsic JSX elements with button role and no keyboard activation. Pass native buttons and handlers on keyboard events. Keep custom components and spreads out of the initial matcher. |
| `validation.runtime-boundaries` | Direct cast of recognized Fetch JSON to a concrete TypeScript domain type. Pass unknown types, schema-validated values, and arbitrary methods named json. |
| `observability.metric-units` | OTel HTTP request duration histogram recording explicit milliseconds or declaring a mismatched unit. Pass seconds and metrics with unrelated names. Preserve current cardinality rules under their own label. |

## 3. Identity, paths, and API ownership

Use the current control-flow and identity facilities where their language
lowering preserves the relevant control. Extend the framework analyzers
for API-specific lifecycle semantics. Give a finding the incorrect call
or exit as its primary location and the original acquisition or binding as
a related location where available.

| Subcategory | Failing and passing evidence |
| --- | --- |
| `protocol.response-lifecycle` | Same Fetch Response consumed twice along a reachable path. Pass mutually exclusive reads, distinct Response objects, and pre-consumption clones. |
| `protocol.status-handling` | Known fetch result immediately decoded as success without an effective status guard. Pass guards, explicit handling of error responses, and response forwarding. |
| `io.concurrent-writes` | Known Node promise-based writes of the same proven path in Promise.all. Pass sequential writes and distinct paths. |
| `frontend.effect-cleanup` | React effect owns a native interval with no cleanup or a different timer in its disposer. Pass aliases to the same timer and cleanup on all applicable paths. |
| `testing.mock-lifecycle`, `testing.isolation` | Jest shared state spy escapes a test. Pass explicit restoration, scoped disposal, afterEach restoration, and configured restoreMocks. Exercise existing process-state checks as regression fixtures. |
| `persistence.transaction-boundaries`, `persistence.data-integrity` | Resolve Go database/sql parent DB and Prisma outer client writes during a transaction. Pass transaction receiver aliases, separate databases, and writes after transaction exit. Keep Spring and SQLx rules in the same grouping. |
| `messaging.acknowledgements` | RabbitMQ manual ack in finally after processing may fail. Pass success-only ack and a separate reject or requeue path. Require a recognized broker receiver. |
| `concurrency.cancellation-safety` | A Tokio select loop recreates read_exact after a competing branch wins. Pass cancellation-safe reads and one retained, pinned future. |
| `memory.initialization` | A fresh Rust Vec raises length beyond its initialized prefix. Pass proven writes before the length change and leave opaque FFI writes unclassified. |
| `observability.trace-propagation` | A known tracing integration starts a child operation from a fresh context despite an available parent. Pass derived and explicitly extracted contexts. |
| `reliability.backpressure` | Repeated writes to a known Node Writable ignore its false return. Pass a reachable drain wait, pipeline-based forwarding, and unrelated write methods. |
| `reliability.retries` | A known remote-client retry loop has no recognized deadline or attempt budget. Pass bounded loops and configured client policies. Add a narrower retry-on-write advisory only for known non-idempotent operations. |
| `reliability.deadlines` | A known remote-client path explicitly disables its timeout and supplies no request deadline. Pass inherited deadlines and bounded requests. Keep cancellation propagation checks grouped. |
| `reliability.shutdown` | A recognized executor or worker owner initiates shutdown and exits without joining work where its contract requires it. Pass join or await and deliberate immediate termination. |

## 4. Configured rules and diff-aware packs

Run only with the relevant artifact or declared policy. Keep each pack
independently selectable. Preserve configuration and discovery behavior
for existing packs. Diagnostics should point to the changed key, statement,
or schema field.

| Pack | Initial contract and regression cases |
| --- | --- |
| `messaging.atomic-publication` | Configure database write and broker publication identities that belong to one operation. Flag a configured dual write outside the outbox contract. Pass an approved outbox write and unrelated publications. |
| `deployment.migrations` | Detect PostgreSQL CREATE INDEX CONCURRENTLY with proven transaction-wrapping migration configuration. Pass the same statement in a non-transactional migration and ignore unknown dialects. |
| `build.dependency-integrity` | Parse workflow YAML and check third-party action references against an opt-in immutable SHA policy. Pass full commit SHAs and local actions. |
| `internationalization.message-contracts` | Compare locale catalog keys and ICU argument sets. Flag dropped required placeholders and missing plural other. Pass locale-specific valid plural categories and handle nested messages. |
| `compatibility.schema-evolution`, `compatibility.rolling-upgrades` | Compare base and head Protobuf schemas. Detect field-number reuse, unreserved deletions, and incompatible changes observable during mixed-version rollout. Pass reserved removals and compatible additions. |

## Verification and delivery

Build in the order above, with independent rule families landing as they
pass verification. Check pattern catalogs, framework integration tests,
TSX parity, and pack opt-in behavior. Run locked workspace tests and
Clippy. Replay representative failing and passing changes through the
normal static CLI, checking rule ID, primary and related locations,
subcategory selection, and absence of duplicate diagnostics. Review the
full change with Autoreview and distinguish deliberately failing fixtures
from findings in implementation code. Keep the delivery goal active until
every row is implemented and its acceptance cases are verified.

## First implementation

The Fetch lifecycle and status checks use the JavaScript and TypeScript
control-flow graph, including TSX. They follow local response aliases,
reassignments, clone identities, and supported status branches. They
recognize global Fetch and explicit imports from Undici and node-fetch.
The status rule also recognizes the direct returned promise callback
case. The TypeScript assertion rule uses the same response identity
before reporting a direct cast to a concrete type. Helper return
values, dynamically selected response methods, and
arbitrary user-defined guards are outside this first implementation.
The Node write check starts with equal string-literal paths, and the OTel
check starts with an explicitly wrong unit on a known metric. These
limits keep the matches reproducible while the framework analyzers
grow alias, control-flow, and helper resolution.

The first reliability labels cover known timeout, cancellation, and
retry rules. `autoreview rules list --subcategories reliability --json`
lists built-in rules in that group. `autoreview explain <finding-id>`
shows the labels saved in the finding. The first catalog includes
pattern, flow, threshold, framework, Rust-specific, and artifact rules.

React interval cleanup now traces aliases through direct setup and
cleanup branches. The Prisma check resolves the outer client through
module-level aliases and distinguishes unrelated clients. The GitHub
Actions pack checks external references in changed workflow files when
the repository opts in:

```yaml
artifactChecks:
  immutableGithubActionRefs: true
```

It reports unpinned action steps and reusable workflows with a
single-line `uses` value. Local actions and full commit SHAs pass.

Additional local checks report an ignored Node writable-stream
backpressure signal in a recognized producer loop, use of a fresh
context when a Go tracer has a parent parameter, and a Rust vector
length increase beyond the initialized prefix of a fresh allocation.
The vector check counts straight-line pushes, literal resizes, and
writes to literal spare-capacity indices. It reports gaps in the prefix
and leaves opaque mutations, pointer escapes, and conditional writes
unclassified.

Existing high-cardinality metrics rules use
`observability.metric-cardinality`. Spring, SQLx, Go and Prisma
transaction checks appear under both `persistence.transaction-boundaries`
and `persistence.data-integrity`.

Go transaction checks follow typed database parameters, aliases, begin
errors, and commit or rollback through supported branches. The Tokio
check flags direct `read_exact` futures recreated in a loop with a
competing `select!` arm. It resolves the macro and receiver type.

Jest spy cleanup covers explicit restoration, cleanup in `finally`,
`using`, and visible `afterEach` hooks. A JSON Jest configuration or
the `jest` section of `package.json` can own automatic restoration.
Dynamic Jest configuration is left unclassified. RabbitMQ checks
manual delivery acknowledgements in `finally` when the corresponding
try body can fail.

The reliability catalog includes Go HTTP checks for an explicitly
disabled timeout, direct retries without a budget, repeated POSTs,
and graceful shutdown using a context that has already been canceled.
The Java executor rule recognizes JVM shutdown hooks using a method
reference or lambda. It follows normal hook exits and flags a
`shutdown()` call when a path can return without a completion call
on the same executor. A blocking close, a recognized wait, or deliberate
immediate shutdown satisfies this check. Completion hidden inside another
helper and the result of a timed wait are outside the first version.

The PostgreSQL pack uses repository-declared globs for migrations
guaranteed to run inside a transaction. A file with a Flyway sidecar
declaring `executeInTransaction=false` is exempt.

```yaml
artifactChecks:
  transactionalPostgresMigrations:
    - 'migrations/postgres/*.sql'
```

For ICU JSON messages, declare a reference locale and the translations
that share its contract. Changes in either side select the comparison.
The rules identify lost placeholders and selectors that omit `other`,
including selectors nested inside another message.

```yaml
artifactChecks:
  localeCatalogs:
    - reference: locales/en.json
      translations: [locales/fr.json, locales/de.json]
```

The Protobuf pack compares matching changed files in the review's merge
base and head. It identifies messages by package and nesting, including
moves between selected files. It reports reused or unreserved field
numbers, type and cardinality changes, and changes that move a field into
or out of a multi-field oneof. Whole-message removal, enum values, and
compiler-specific options are outside the first version.

```yaml
artifactChecks:
  protobufCompatibility:
    - 'schemas/**/*.proto'
```

The outbox policy uses explicit pairs of imported operations. Each pair
defines the database write and direct broker publication that need to
be atomic on the configured paths. The broker selector can restrict the
first argument to a literal event name. Use the imported transaction
helper as the database operation when it represents the business write.

```yaml
artifactChecks:
  outboxOperations:
    - paths: ['src/orders/**/*.ts']
      databaseWrite:
        module: './orders'
        export: 'repository'
        members: ['update']
      brokerPublish:
        module: './events'
        export: 'publish'
        firstArgument: 'orders.updated'
```

JavaScript, TypeScript and TSX checks report a direct publication when
the paired write is reachable in the same function or callback. The
report points to the broker call and links to the database call. An
operation that writes its event to an outbox and leaves delivery to a
separate worker passes, as does a publication for a different event.
The check resolves static import aliases and member paths. Calls reached
only inside a helper and dynamic topic values require a directly
configured wrapper or a follow-up extension.
